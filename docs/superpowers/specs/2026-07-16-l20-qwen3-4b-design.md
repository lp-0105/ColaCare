# L20 Qwen3-4B 离线部署准备设计

日期：2026-07-16

## 目标与边界

本分支从 `local-small-llm` 的稳定提交
`5374852ed2a082a37ada3102c6b91d0c94eda232` 开始，只准备 L20 的离线资产、
直接 Transformers 冒烟链路和后续 vLLM 切换说明。当前阶段不下载模型、不上传服务器、
不安装包、不修改共享 Conda 环境、不启动 vLLM，也不处理 MIMIC 或任何患者数据。

## 已批准的实现方案

1. 固定使用 `Qwen/Qwen3-4B-Instruct-2507`，首个可重复快照 revision 为
   `cdbee75f17c01a7cc42f958dc650907174af0554`。
2. 有网机器用 `huggingface_hub.snapshot_download` 下载完整标准 Transformers/
   Safetensors 快照，生成逐文件清单与 SHA256，再单独打包模型和指定 Git commit 的代码。
3. 代码包由 `git archive <commit>` 生成，天然不带工作树未跟踪文件和 `.git`；脚本再对
   根目录敏感路径与大文件执行拒绝检查。
4. L20 先复用 `/opt/miniconda3/envs/pytorch`，以 BF16、`cuda:0`、4096 上下文、
   batch 1、确定性解码直接运行 Transformers。模型和 tokenizer 都强制
   `local_files_only=True`，并设置 Hugging Face/Transformers 离线变量。
5. 冒烟输入只允许仓库内 `synthetic: true` 的虚构 fixture。输出只保留结构化风险概率、
   二元预测、简短结论和运行指标，写入被 Git 忽略的 `artifacts/l20_smoke/`。
6. vLLM 只保留环境变量兼容面；以后服务启动后，Agent 端只改
   `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL_NAME`。

## 数据流与失败策略

```text
HF 固定 revision -> 完整快照 -> 文件校验/清单/SHA256
                    -> 模型归档与 2GB 分片 -> 网页 VSCode 手动上传
Git 固定 commit  -> 代码归档 ----------^             |
                                                   v
L20 分片校验 -> 合并/解压 -> 离线资产校验 -> Transformers BF16
                                                -> 虚构 EHR JSON
                                                -> 合法结构化预测
```

任一关键文件、哈希、磁盘、GPU、CUDA、Python 包、fixture 标记或 JSON Schema 校验失败均
立即返回非零状态。模型输出解析只重试一次；异常保留完整 traceback，但不把输入患者内容
拼入异常文本。脚本不包含自动安装、联网探测或资源修改逻辑。

## 验收

- 本地单元测试覆盖快照校验/清单、JSON 提取与校验、虚构 fixture 门禁以及脚本安全约束。
- Python 文件通过 `compileall`，所有 shell 文件通过 `bash -n`。
- Git 扫描确认没有模型、`.env`、数据集、患者输出或大型文件。
- 只推送 `origin/l20-qwen3-4b`；`main` 不变且不创建 Pull Request。
